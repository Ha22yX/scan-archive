## 程序界面

![原生 Windows 文档工作台（虚构演示资料）](docs/screenshots/native-workspace.png)

![网页文档库（合成测试数据）](docs/screenshots/web-library.png)

扫描、文档管理、原件预览、AI 概括与秘书对话在同一个原生 Windows 工作台中。选中文档后可以直接提问、翻页、修改归档，点击回答引用即可查看原文。处理记录、回收站与完整设置也是原生界面。

网页是同一文档库的远程访问入口。桌面直接通过当前 Windows 用户专用的本机接口调用文档核心，不内嵌浏览器，也不需要网页登录或 WebView2。

## 为什么做这个项目

纸质文件太多，保存麻烦，翻找更累。我希望把纸放入打印机，点击扫描就留下电子版本，不必为每份资料重新想名字、找文件夹。未来想要的私人知识库，是用一句话找到对应文件和原文页码，同时可靠保留每一份原始扫描。

现在的流程是：先逐页调用 OpenAI 分析，再汇总全文并保存元数据，最后唤醒独立 Agent 决定分类、命名，以及是否把混在一起的独立文件拆分。

默认同时处理 **3 份文档**，每份文档同时分析 **2 页**；桌面和网页设置均可调整并发数。已完成的页面会保存检查点，中断恢复和拆分时可复用。全局最多同时发送 8 个 OpenAI 请求。整理和对话使用独立的串行 Agent 队列，与内容分析并行，避免多个 Agent 同时修改目录。实际速度取决于文档大小、模型响应和 API 限流。

拆分后的文件全部归档、且恰好覆盖原件所有页面时，原始合集自动退出常规列表、搜索和文档计数。漏页、重复页或未处理完成时，合集继续保留在列表。原始扫描仍可通过子文件右键“查看原始扫描”追溯；删除子文件导致覆盖不完整时，合集会重新显示。

## 部署与使用

需要 Windows x64、构建时使用 .NET 10 SDK，以及设备的 WIA 扫描驱动。AI 功能需要 OpenAI 官方 API Key；扫描和预览不依赖 Key。

```powershell
git clone https://github.com/Ha22yX/scan-archive.git
cd scan-archive
.\scripts\publish.ps1
.\dist\ScanArchive.exe
```

1. 桌面设置选择设备、归档目录、分辨率和扫描来源。
2. 如需远程访问，在服务电脑打开 http://localhost:5278，首次创建至少 10 个字符的网页访问密码；桌面本身无需此步骤。
3. 在桌面或网页设置填写 OpenAI API Key。桌面设置也能直接调整模型、每日请求上限、Agent 步数和长期偏好。
4. 设置扫描后自动整理，以及每日巡检时间，默认 Windows 本地时间 **05:00**。
5. 点击扫描：文件先进入 Inbox，桌面直接通过仅当前 Windows 用户可访问的命名管道提交扫描事件，核心返回文档编号后完成交接；内容分析完成后再交给 Agent 整理。桌面与网页自动显示相同的文件记录和处理状态。

默认模型为 `gpt-6-astra` 和 `text-embedding-3-large`，请选择账户支持的模型。页面图片会发送给 OpenAI 官方 API 处理；Key 使用当前 Windows 账户 DPAPI 加密，不写入仓库或在网页返回。

扫描前会读取统一归档目录，避免桌面与网页各用一个目录。交接未确认时，扫描事件保留在桌面发件箱，打开应用后自动重试。桌面文件列表直接读取文档库记录，并显示分析、索引、整理状态。右键删除会同步移入应用回收站，可从整理记录恢复，原始字节保留；正在处理的文件需等待任务结束后删除。关闭扫描窗口不会退出后台服务。也可以用 `scripts/start-secretary.ps1` 启动；希望登录 Windows 自动启动时，手动执行 `scripts/enable-startup.ps1`，用 `-Disable` 取消。电脑须开机且归档盘可访问，错过的最近一次每日巡检会在恢复后补执行。它不负责唤醒休眠电脑，也不是登录前启动的系统服务。

局域网用 `http://电脑IP:5278` 和同一密码访问。如防火墙拦截，在管理员 PowerShell 执行 `scripts/enable-lan.ps1`，仅允许专用网络的本地子网访问。默认使用 HTTP，适合可信局域网；不要直接映射到公网，远程使用需另配 HTTPS 访问网关。

## 桌面操作

- 左侧文档列表支持分类、状态筛选和每批 60 份的分页；后台刷新保留选中文档及阅读页码。
- 中间显示原件，支持上下页、输入页码和系统阅读器打开。PDF 渲染在后台执行，避免阻塞操作。
- 文档详情支持原生 Markdown 渲染：标题、加粗、列表、引用、代码和表格。后续 AI 概括按分节结构生成；已有概括可点击“Markdown 整理”，复用当前概括而不重新扫描，修改前后版本保存到数据库和 JSON 元数据。右键可复制 Markdown，HTML 与外部图片不会执行或加载。
- 右侧查看详细概括、关键词、扫描时间与当前页识别原文，或切换到秘书对话。可附带当前文档/页码，继续历史对话，点击引用回看证据。
- 右键或详情按钮可修改标题与分类、解锁自动归档、删除；处理记录可重试任务、撤销移动、恢复回收站文件和立即唤醒秘书。
- 快捷键：`Ctrl+F` 搜索、`F5` 刷新、`Ctrl+Enter` 发送对话，文件列表中 `Delete` 弹出删除确认。

## 内容、元数据与搜索

| 能力 | 说明 |
| --- | --- |
| 逐页理解 | 识别全文、表格和公式，保存详细概括、主题、人名机构、日期编号、双语关键词及识别不确定性 |
| 全文概括 | 所有页面参与文档摘要，长文档分组汇总，不直接丢弃后面的页 |
| 元数据 | 数据库和每文件 JSON 双份保存，包含固定 ID、内容哈希、扫描时间、分析时间、模型和原件关联 |
| 自动整理 | Agent 自由创建语义分类、改名、移动、合并分类、拆分 PDF，并保留源文件 |
| 混合搜索 | 中文双字分词、全文检索、精确编号和向量语义检索融合，结果定位到页 |
| 秘书交互 | 多角度查询后读取原文核对，回答附可点击页码引用 |
| 每日巡检 | 检查分类结构、标题、索引覆盖和长期偏好，执行有价值的优化 |
| 恢复能力 | 逐页断点、失败重试、操作记录、移动撤销；手动分类可锁定 |

扫描时间与文档中印刷的日期分别保存。拆分文件继承扫描时间并记录源文件 ID、原始页码范围。后台不再自动遍历归档目录。旧文件需要用桌面“导入文件”、网页上传或点击一次性手动导入；缺少扫描事件的旧文件使用创建时间作为回退，复制过的文件可能不准确。完全相同的字节文件共用一个文档记录，每次扫描事件另外保留扫描时间、设备和来源；文件改名后重试交接也不会重复入库。

## 数据存在哪里

归档根目录下，`Inbox` 接收扫描，`Library/<分类>` 存放整理后的文件，`.scanarchive-originals` 保留原始字节，`.scanarchive-metadata` 保存逐份 JSON。数据库、任务、聊天记录和设置位于 `%LOCALAPPDATA%\ScanArchive\Secretary`。

备份时应关闭服务，并同时备份归档根目录和上述本地数据目录。原件保留在同一硬盘不等于异地备份。更换 Windows 账户后需重新配置 Key。目前尚未实现仅用 JSON 自动完整恢复数据库的迁移工具。

## 技术与验证

C# / .NET 10 WinForms、WIA / 原生 WIA 2.0 进纸器、PDFsharp、Docnet/PDFium；后台为 ASP.NET Core + SQLite/FTS5，网页使用原生 JavaScript/CSS。OpenAI Responses API 负责结构化分析和工具调用，embeddings 用于语义检索。Responses 使用 `store:false`，这不意味着扫描内容不会被传输给 API。

```powershell
dotnet test ScanArchive.Server.Tests -c Release
.\dist\ScanArchive.exe --self-test
```

自动测试使用合成 PDF 与模拟 API，验证分析顺序、元数据、中文编号搜索、向量失败回退、拆分追溯、移动撤销、引用核对及每日调度。模拟测试不能代表真实模型的识别准确率；还需配置真实 Key，用代表性文档评估。手写、模糊或截断的内容可能误识别，重要结果请核对原文。

按页索引只使用该页内容，避免混合扫描的全局关键词使无关页面误命中。整体文档元数据仅作为低权重发现线索，仍需核对原文。旧索引会自动升级一次，复用已完成的页面分析；重建中断也保留原有检索覆盖。

当前向量检索在进程内计算，超大文档库后续需要专用索引。每日请求数限制不是金额上限；Agent 单次步数有限，大规模整理可能需要多次唤醒。
