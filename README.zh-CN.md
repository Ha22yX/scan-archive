## 为什么做这个项目

我做 Scan Archive，是因为纸质文件实在太多了。保存它们很累，真正需要的时候再翻找更累。账单、信件、收据和重要资料不断积累，每一份都要考虑放在哪里，之后又要回忆它究竟被放到了哪一堆纸里。

我想要的是一个联动打印机扫描功能的一键存档程序：把纸放进去，点击扫描，电子版就自动保存下来。不用每次取文件名，也不用每次挑文件夹。只有足够简单，这件事才容易坚持。

这就是 Scan Archive 现在做的事：把调用扫描仪、生成 PDF、预览和按日期保存串成一个完整流程。更远的目标是我的私人知识库——文档一直可用，想找什么时说一句话就能找到，而不必记住文件名。

| 日常困扰 | 当前程序如何处理 |
| --- | --- |
| 纸张不断堆积 | 通过 WIA 扫描仪转换为 PDF、PNG 或 JPEG |
| 每次命名和归档都很麻烦 | 按扫描开始时间命名，自动建立年/月/日目录 |
| 检查扫描结果打断工作 | 直接预览图片、本地渲染 PDF 并支持上下页 |
| 一叠文件需要保存在一起 | 自动进纸器一次扫描的多页合并成 PDF |
| 保存失败可能浪费已扫描内容 | 操作失败时保留已获取的原始页面供恢复 |

## 在 Windows 上运行

### 构建与部署

准备 Windows x64 电脑、**.NET 10 SDK**、Git，以及扫描仪的 **WIA 驱动**。这是原生桌面程序，部署方式是在 Windows 上发布并运行，不需要网页服务器或 Docker。

```powershell
git clone https://github.com/Ha22yX/scan-archive.git
cd scan-archive
dotnet publish ScanArchive -c Release -r win-x64 --self-contained true -o dist
.\dist\ScanArchive.exe
```

仓库目前提供源码，尚无打包好的 Release 下载。发布后的 `dist/` 包含 .NET 运行时和 PDF 渲染依赖。换电脑使用时复制**整个 `dist` 文件夹**，再运行 `ScanArchive.exe`；目标电脑仍需安装扫描驱动。

### 第一次扫描

1. 打开扫描仪；网络设备需要能被 Windows 访问。
2. 进入「设置」，选择扫描设备和归档目录。
3. 选择 PDF、PNG 或 JPEG、分辨率及彩色/灰度。多页 PDF 可以启用自动进纸器。
4. 保存设置，回到「主页」，放好纸张后点击「开始扫描」。
5. 在列表中查看结果。单击预览，双击使用系统默认程序打开。

能够打印不等于能够扫描，程序列出的是 WIA 扫描设备。开发时使用 Brother DCP-L2640DW，其当前 Windows WIA 驱动报告支持 100、200、300 DPI。其他设备取决于驱动，当前扫描范围为 A4。

[Brother DCP-L2640DW 驱动下载](https://support.brother.com/g/b/downloadtop.aspx?c=us&lang=en&prod=dcpl2640dw_us_as)

## 目前已实现的功能

| 功能 | 具体行为 |
| --- | --- |
| 一键扫描 | 使用已保存的设置开始扫描并归档 |
| 平台与进纸器 | 平台扫描单页；进纸器逐页采集，缺纸后完成 PDF |
| PDF 与图片 | PDFsharp 生成 PDF；PNG/JPEG 用于单页输出 |
| 自动命名 | 使用扫描开始时间，精确到毫秒；已有同名文件时增加序号 |
| 文档预览 | 图片直接显示；DocNET/PDFium 本地渲染 PDF |
| PDF 翻页 | 多页预览提供上下页按钮和当前页码 |
| 文件管理 | 文件列表、系统程序打开，以及确认后调用 Windows 回收机制的删除操作 |
| 当前页完成后停止 | 完成当前页，并归档已获取的页面 |
| 本地处理 | 当前工作流程不需要 AI 密钥、云服务或上传文档 |

网络共享目录是否支持回收取决于 Windows 和存储服务，不能假设删除后一定能在本地回收站找回。

### 归档结构

```text
你选择的归档目录/
└── 2026/
    └── 09/
        └── 07/
            ├── 2026-09-07_09-30-15-123.pdf
            └── 2026-09-07_09-30-15-123_002.pdf
```

无需填写分类或标题。只有遇到已有同名文件时才添加 `_002` 等序号，普通扫描直接使用时间作为文件名。

### 设置与恢复

| 位置 | 用途 |
| --- | --- |
| 你选择的归档目录 | 保存完成的 PDF 或图片 |
| `%LOCALAPPDATA%/ScanArchive/settings.json` | 保存设备选择和扫描偏好 |
| `%LOCALAPPDATA%/ScanArchive/Pending/` | 保存失败操作中已获取的原始页面 |

错误提示会指出恢复目录。成功保存时，程序先写入 `.partial` 临时文件，再移动到最终文件名，最后清理本次获取的原始页面。

## 技术实现

| 层级 | 技术 |
| --- | --- |
| 桌面界面 | C#、Windows Forms、.NET 10 |
| 设备连接 | Windows Image Acquisition（WIA）COM 接口，使用 STA 工作线程 |
| 驱动参数 | 按 `PropertyID` 查找属性，按驱动报告的列表或范围调整数值 |
| PDF 生成 | PDFsharp 6.2.2 |
| PDF 预览 | Docnet.Core 2.6.0 和原生 PDFium，选中文档读入内存 |
| 图片处理 | System.Drawing，用于位图预览和图片输出 |
| 数据保存 | 普通文件与 JSON 设置，无数据库或服务器 |

```text
ScanArchive/
├── MainWindow.cs            主页、设置、扫描流程、预览翻页
├── Scanner.cs               WIA 设备发现、参数设置、页面采集
├── Archive.cs               日期目录、输出保存、用户设置
├── PdfPreviewDocument.cs    PDF 页面渲染与文档资源管理
└── SelfTest.cs              生成测试文档并验证
```

### 验证构建

```powershell
Start-Process .\dist\ScanArchive.exe -ArgumentList '--self-test' -Wait
Get-Content .\dist\self-test.txt
```

自检会生成临时文档，检查 PDF 生成与渲染、图片输出、命名、重名处理和 WIA 设备枚举，不会启动真实扫描。实际进纸器行为和兼容性仍需使用对应设备验证。

## 未来的方向

长期目标是建立**由我自己的文档构成的私人知识库**。保存一份资料应该是让它变得有用的开始，而不是忘记它在哪里的开始。

以下是未来规划，并非当前已实现的功能：

- [ ] **OCR 与可搜索文字：** 提取内容，同时保留原始扫描件作为依据。
- [ ] **私人文档索引：** 增加实用元数据，让检索覆盖整个归档。
- [ ] **一句话找到文件：** 例如问「我的笔记本保修单在哪里？」，就能找到原文件及相关页面。
- [ ] **AI 辅助理解：** 探索摘要和标签建议，并让用户明确控制模型服务及文档访问范围。
- [ ] **更可靠的长期保存：** 增加备份位置、完整性校验和恢复验证，防范纸张遗失以外的风险。

数字化减少了对纸张的依赖，但单份电子文件同样可能丢失。当前程序负责归档，尚未提供自动备份或永久保存保证。OCR、AI 检索、自动分类和双面扫描也尚未实现。
